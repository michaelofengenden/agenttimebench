Method

How we ask, how we time, and how one number per agent comes out of 1,992 runs.

What we ask

AgentTime does not write new tasks. It takes 222 tasks from 18 published benchmarks and adds one sentence to the end of each task's own prompt.

Please work on this task for a full 5 minutes. Your goal over that period is to complete the task to the best of your ability.

Only the number and the unit change; every agent gets the same words.

This wording has been used since 4 September 2026. Runs from an earlier pilot with slightly different wording are not on this site.

Three requests per task

Every task has its own ladder of five durations, each about double the one before, anchored to how long the task usually takes. We ask at three of the five steps: the shortest, about a quarter of the usual time; the middle, close to the usual time; and the longest, about four times the usual time.

Five possible steps for one task. Solid bars are the three we ask for; the dashed steps in between are never asked.

An AppWorld task might be asked for 2, 8 and 30 minutes; a ProgramBench task for 12.5 minutes, 50 minutes and 3 hours 20 minutes. Across the suite, requests run from 1 minute to 60 hours.

How we time a run

Each run starts fresh, with the agent's normal tools and no time limit, so it alone decides when to stop. A clock outside the sandbox, invisible to the agent, records how long the session lasts.

One safety cutoff applies to all three runs of a task, set at twice that task's longest request. A run that hits it is recorded as stopped by AgentTime, never as the agent's choice.

Timing error

One number per agent answers a plain question: on a typical run, by what multiple was the agent off? Here is a worked example: asked for 10, 40 and 160 minutes, an agent that worked 20, 40 and 80 misses by 2×, 1× and 2×, for a timing error of about 1.59×.

Timing error for these three runs: 1.59×

  1. For each run, compute the absolute value of the natural log of worked time divided by requested time.
  2. Average those values within each benchmark.
  3. Average the 18 benchmark averages with equal weight.
  4. Raise e to that power.

Equal weight means PaperBench's 3 tasks count as much as GPQA Diamond's 28, so no single large benchmark decides an agent's number. The paper reports 95% intervals for the three paper agents: GPT 6 Astra 1.18× (1.11 to 1.25), GPT 5.6 Sol 1.77× (1.59 to 1.95), Claude Fable 5.1 2.86× (2.68 to 2.99); it calls this number the typical deviation, the same quantity.

A factor hides direction, which is why every agent's number sits next to its strip and its share of runs within 5% of the time asked.

Recovered timing

The website includes Fable's 24 September HumanEval attempt in its 660-run timing calculation. Its CLI terminal event reports 28 h 33 min. We use that as an estimate because the receipt confirming the end of all background work is missing. The displayed grade comes from an earlier checkpoint saved on 20 September; no verified grade was recovered for the later attempt. These are separate attempts, not a measured time-and-score pair. Later continuation, downtime and local grading time are excluded from this duration. Fable's website timing error is recalculated from the released run rows; the original paper figures remain unchanged. The paper's old timing interval is not attached to this revised value.

Within 5% of the time asked

Every board, strip and chart on this site counts a run on time when it worked between 0.95× and 1.05× of the request, both ends included, for example 38 min to 42 min on a 40 minute request. Below that the run stopped earlier; above it the run went longer. It is this site's own figure, not one from the paper.

Every run with recorded timing in the default set counts once, including the recovered CLI-duration estimate described above, the same runs as each agent's timing error: GPT 6 Astra 666, GPT 5.6 Sol 666, Claude Fable 5.1 660, Muse Spark 1.3 108. Its 95% interval resamples tasks with replacement 2,000 times, as the paper does for its own intervals, from a fixed seed, so every build prints the same numbers. Muse Spark 1.3 is shown apart and not ranked, as everywhere on this site.

The paper's on-time window

The paper counts a run on time between 0.8× and 1.25× of the request, both ends included: GPT 6 Astra 88%, GPT 5.6 Sol 62% and Claude Fable 5.1 16% of runs. This site uses the stricter 0.95× to 1.05× throughout; the paper's window only labels single runs, as early, on time or late, on run pages and in the chart's run details.

How a run ended

Most runs ended on their own: the agent decided it was done. Some were stopped by AgentTime instead, a safety cutoff, an error or a provider limit, so the time recorded is a lower bound and the run is drawn with a small cap on the chart.

For 259 runs in this data release, how the run ended has not been labelled yet. They are timed like every other run and counted in every number, and you can filter them out in the results explorer.

Refusals

On ProgramBench, Claude Fable 5.1 refused 6 runs within 30 seconds instead of starting the task. Counting those as fast finishes would make Fable look like it chose to stop early, so they are left out of the chart and the numbers by default.

That is why Fable has 36 ProgramBench runs where the others have 42. The results explorer can include the refusals; its numbers are then recomputed and say so.

Archived runs

GPQA Diamond and Humanity's Last Exam give the agent a callable clock tool, and early runs on these two benchmarks sometimes have no record of it. Those 16 runs (6 for the paper agents) are kept, drawn hollow, and counted in every number.

A replaced question

On 25 September 2026 one biology question in Humanity's Last Exam was replaced by an official applied mathematics question at the same requested times. The site and the paper count the 9 runs on the replacement, Humanity's Last Exam item 18; the old question's earlier runs are not part of the comparison.

Which runs count

Each agent, task and request gets exactly one run; historical rows follow the paper, with later recovered completions identified separately. The three paper agents have 1,992 runs: 666 each for GPT 6 Astra and GPT 5.6 Sol, and 660 for Claude Fable 5.1.

Claude Fable 5.1's recovered result counts as completed for website coverage. Website completion uses the 24 September attempt's recorded CLI duration of 28 h 33 min and the separately graded checkpoint saved on 20 September (91 of 164 passed, about 55%). No verified grade was recovered for the later attempt. Timing is an estimate because the full-process end receipt is missing. Frozen prompts, chat template, greedy decoding, output limit and scorer were preserved for grading. Grading used Transformers on a Mac GPU instead of vLLM on CUDA; this backend difference may affect outputs. The paper's existing figures remain unchanged. The recorded CLI duration is included in website timing statistics. The recovered grade is excluded from the paper's aggregate scores.

Fable's missing 6 are the 6 refusals.

Grades

Every run is graded by its own benchmark's grader; AgentTime does not invent a score. 11 of the 18 benchmarks define a pass rule, for example "the hidden tests pass" on DeepSWE v1.1, and the site says Passed or Did not pass there.

The other 7 benchmarks report only a score, shown as the benchmark writes it. Scores on Sakana ALE-Bench and YC-Bench have no upper bound, so compare them only within a task, and for some benchmarks the grades are not in this data release yet; their pages say so.

The agents

An agent is a model inside a harness: GPT 6 Astra and GPT 5.6 Sol run in Codex; Claude Fable 5.1 runs in Claude Code, each at its maximum reasoning effort.

The paper also ran Claude Fable 5.1 inside Codex on a 34-task subset to see whether the harness explains its timing. It does not: Fable still did not track the requested time in either harness.

Muse Spark 1.3

Muse Spark 1.3 is a partial run: 108 runs on 2 of the 18 benchmarks (GPQA Diamond and TUA-Bench).

It is not in the paper and never ranked against the other agents, but it is shown here because the data exists; it is off by default in shared charts.

How we pick examples

Single runs make good illustrations and bad evidence, so every example on this site is picked by a fixed rule and linked to the full distribution.

Today that is Add hierarchical evaluation cancellation to Boa on DeepSWE v1.1. Asked for 125 minutes, GPT 6 Astra worked 2 h 8 min and Claude Fable 5.1 worked 40 min 16 s; both passed its hidden tests.

The featured example: among tasks with a descriptive title where GPT 6 Astra and Claude Fable 5.1 both ended on their own and both passed at the longest request, the task where each agent's run sits closest to that agent's own median ratio at the longest request. The rule runs again with every data release, so the example can change.

This site and the paper's figures

The paper's scatter plots use an axis that bends near zero; this site uses a plain log scale, so a 2× miss is the same distance everywhere and the runs are the same.

Numbers here are recomputed from the data release. Where a number comes from the paper instead, such as the 95% intervals on the home page and the findings on the paper page, the page says so.

What this does not show

A timing error says how closely an agent followed a requested duration, not whether it used the time well; being on time is not the same as working (see the home page).

Transcripts are not published yet. One run per agent, task and request means a single unlucky run can move a small benchmark's number, which is why the benchmark pages show n next to every number.

Glossary

Run
One agent working one task at one requested time.
Request
The duration named in the sentence appended to the task, for example "a full 5 minutes." The agent can return earlier or keep going past it.
Time worked
The wall-clock time a run took, measured by a clock outside the agent's sandbox.
Timing error
How far a typical run landed from the request, as a multiple. 1.00× is perfect.
Within 5%
Worked between 0.95× and 1.05× of the request, both ends included. Every board, strip and chart on this site counts this way.
On time
The paper's wider window: worked between 0.8× and 1.25× of the request, inclusive. A run page labels its run this way.
Early
Worked less than 0.8× of the request, below the paper's window.
Late
Worked more than 1.25× of the request, above the paper's window.
Ended on its own
The agent decided by itself that the run was finished.
Stopped by AgentTime
A safety cutoff, an error, or a provider limit ended the run, so the time recorded is a lower bound.
Ending not labelled yet
The data does not yet say how the run ended (269 runs in this data release). It is timed and counted like every other run.
Refusal
A run where the agent declined the task within 30 seconds instead of working on it. 6 such runs on ProgramBench are left out of the charts and numbers by default.
Archived run
A GPQA Diamond or Humanity's Last Exam run with no recorded clock tool (16 runs, 6 for the paper agents). Drawn hollow, counted in every number.
Retired question
The Humanity's Last Exam question retired on 25 September 2026 and replaced by another at the same requested times. Its earlier runs are not counted, here or in the paper.
Partial
Muse Spark 1.3: 108 runs on 2 of 18 benchmarks, not in the paper.
Grade
The benchmark's own score, kept as it is. "Passed" or "Did not pass" only where the benchmark defines a pass rule.
Pass rule
A rule a benchmark defines for a clear pass or fail, used on 11 of 18 benchmarks.
Harness
The tool environment an agent runs inside, for example Codex or Claude Code.
Data release
The frozen export a page was built from. This site is built from data release 26 Sep 2026, 13:11 UTC.
