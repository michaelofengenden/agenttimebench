## Dashboard status interface

GET /api/pilot-status reads a JSON snapshot. schema_version1; campaign_id; snapshot_at; source_observed_at; refresh_seconds5; stale_after_seconds30; campaign{phase,model,effort,route,selected_tasks,target_concurrency,paused_reason}; counts{preparing,ready,running,waiting,finished,blocked,unknown,active_native,peak_active_native}; concurrency[{at,running,waiting,unknown}]; tasks[{task_id,label,benchmark,attempt_id,state,detail,heartbeat_at,prompt_released_at,native_terminal_at,owned_work_drained_at,stop_verified,timing:{status,elapsed_seconds,runtime_seconds,reason},grade:{status,value,scale},archive:{status,restore_status},issue:{code,message}|null}].

Running requires authoritative native prompt release, not a living worker. Waiting requires an identified native/tool/process wait, not silence. Unreachable work is unknown and continues to hold capacity. Finish means owned work drained; correctness, archive acknowledgement and timing validity are separate. Concurrency history derives from persisted source events, never browser interpolation. Zero observed model work remains zero until evidence exists.
