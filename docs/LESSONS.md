# What v1 taught us

These are requirements for the new build, drawn from the retained audits. They are not claims that every historical attempt failed in these ways. Source paths and hashes are in [provenance.json](provenance.json).

| What went wrong or remained uncertain | What v1.1 must prove |
| --- | --- |
| Wrapper or job duration mixed setup, agent work and grading. | Record prompt release and native completion separately from the other phases. |
| Removing the duration paragraph could leave a native timer, turn ceiling or inactivity limit. | Exercise the actual deployed route beyond each old work limit. Preserve task-defining endpoints. |
| Final perfect scores were mistaken for first-success times. | Report natural finish and final quality separately. Claim first success only with direct evidence. |
| Errors, missing onset evidence and absent score methods could look like ordinary results. | Keep platform failure, agent outcome, raw grade and admission separate. Missing is not zero. |
| Some verifiers were flawed, and some environments started broken. | Audit pinned source, test correct and incorrect submissions, and smoke-test initial state before study use. |
| Background work and unsaved live state complicated submission capture. | Qualify a preservation contract for each task; prevent later work from improving the graded submission. |
| Reused homes, prompts and sessions could contaminate new attempts. | Start fresh and record the exact task, model and delivered prompt identities. |
| Capacity claims, provider limits and stale ownership were confused. | Reserve resources and provider capacity separately; use durable ownership and explicit attempt IDs. |
| Restart or capture failure could lose evidence or risk duplicate execution. | Recover the existing session first; fence uncertain work; allow only the selected one-replacement policy. |
| Shutdown and dashboard status were mistaken for stronger evidence. | Verify uploads before teardown. Rebuild displays from dated evidence; a display repair cannot admit a run. |

Old prompted attempts can inform risk and cost estimates. They cannot supply natural-runtime calibration merely because their measured duration is available. Comparable genuinely untimed older runs remain candidates for the later calculation.

The earlier complete acceptance checklist and audit sources remain in the original repository. This repository records their hashes and locations without copying old runtime state, credentials or submissions.
